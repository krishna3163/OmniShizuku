# OmniShizuku — V1.0.0 Release Pipeline Execution Guide

## Overview
This document provides complete instructions for release managers and maintainers to trigger, monitor, verify, and distribute the official **OmniShizuku v1.0.0** release using the automated GitHub Actions CI/CD pipeline.

---

## 1. Pre-Release Verification Checklist

Before triggering the release workflow:
- [x] All unit tests pass: `./gradlew :manager:testDebugUnitTest --no-daemon`
- [x] APK compiles cleanly: `./gradlew :manager:assembleDebug :manager:assembleRelease --no-daemon`
- [x] `defaultVersionName = "v1.0.0"` is confirmed in `build.gradle`
- [x] All GitHub Code Scanning security alerts remediated
- [x] Working tree is clean and committed on release branch `release/v1.0.0-engineering`

---

## 2. Triggering the Release Pipeline

The release pipeline (`.github/workflows/release.yml`) is protected by an **Owner Gate** that permits only `krishna3163` to publish official releases.

### Method A: Via GitHub CLI (`gh`)
```bash
# Trigger the release workflow with tag v1.0.0
gh workflow run release.yml \
  --ref release/v1.0.0-engineering \
  -f tag="v1.0.0" \
  -f title="OmniShizuku v1.0.0 — Production Release" \
  -f prerelease="false"
```

### Method B: Via GitHub Web Interface
1. Navigate to `https://github.com/krishna3163/OmniShizuku/actions/workflows/release.yml`.
2. Click **Run workflow**.
3. Select branch: `release/v1.0.0-engineering` (or `main` after merging).
4. Fill in inputs:
   - **Tag to release:** `v1.0.0`
   - **Release title:** `OmniShizuku v1.0.0 — Production Release`
   - **Git ref:** `release/v1.0.0-engineering`
   - **Pre-release:** unchecked (false)
5. Click **Run workflow**.

---

## 3. Pipeline Stages & Execution Flow

```text
[Owner Gate] -> [Tag Validation] -> [Setup JDK 21 & SDK 37.1]
     |
[Configure Signing] (Uses KEYSTORE_BASE64 or generates debug keystore)
     |
[Run Unit Tests] (:manager:testDebugUnitTest)
     |
[Build APKs] (:manager:assembleRelease & :manager:assembleDebug)
     |
[Upload Artifacts] (manager-release-apk & manager-debug-apk)
     |
[Publish Release] (gh release create v1.0.0 with universal APKs)
```

---

## 4. Release Artifact Verification

Once the pipeline completes, download the generated release assets and verify their signatures:

```bash
# Verify APK signature schemes (v1, v2, v3)
$ANDROID_SDK_ROOT/build-tools/37.0.0/apksigner verify --verbose release-assets/omnishizuku-v1.0.0.apk

# Expected output:
# Verifies
# Verified using v1 scheme (JAR signing): true
# Verified using v2 scheme (APK Signature Scheme v2): true
# Verified using v3 scheme (APK Signature Scheme v3): true

# Verify checksum integrity
sha256sum release-assets/*.apk
```

---

## 5. Post-Release Distribution

1. **GitHub Releases:** Assets `omnishizuku-v1.0.0.apk` and `omnishizuku-v1.0.0-debug.apk` are automatically attached to the release tag.
2. **F-Droid / IzzyOnDroid:** The repository metadata is prepared for ingestion by F-Droid client repositories using standard tag matching.
3. **In-App Update Checker:** The in-app updater (`SheveryUpdateChecker.kt`) will detect `v1.0.0` as the latest release and notify existing installations.
