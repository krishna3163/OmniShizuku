# Messages Over Other Apps (Overlay & In-App Messaging)

Status: **IMPLEMENTED / INTEGRATED / UNIT_TESTED: VERIFIED (6/6 PASSING) / RUNTIME DEVICE VERIFICATION: BLOCKED (NO ANDROID SDK/DEVICE)**

## Purpose

Display short, temporary, non-intrusive contextual messages while the user is interacting with other apps (such as pairing dialogs, developer options, or external package managers), falling back cleanly to in-app messaging when overlays are disabled or permissions are unavailable.

## Architecture

- `HelperMessageDispatcher`: Pure FIFO message queue decoupling clock (`DispatcherClock`) and delay scheduling (`DispatcherScheduler`) for deterministic unit testing.
  - Prioritizes messages by type and timestamp.
  - Enforces duplicate message suppression within a configurable dedupe window (default 3,000ms).
  - Routes to `OverlayMessageController` if overlay permission is granted and preference is enabled.
  - Falls back to `InAppMessageController` (Compose/Snackbar) when the app is in the foreground.
  - Safely drops background messages if overlay permission is not granted (mandatory pairing results are delivered via standard system notifications).
- `OverlayMessageController`: Android WindowManager implementation using `TYPE_APPLICATION_OVERLAY`.
  - Least-privileged, non-intrusive window flags: `FLAG_NOT_FOCUSABLE or FLAG_NOT_TOUCHABLE or FLAG_LAYOUT_IN_SCREEN`.
  - Pass-through touch behavior ensures no interference with underlying apps.
  - Timed removal via Handler callback with clean `removeAll()` teardown on service destruction or permission revocation.

## Preferences & Permissions

- Preference key: `messages_over_other_apps_enabled` (`ShizukuSettings`), default `false`, independent.
- Requires `android.permission.SYSTEM_ALERT_WINDOW` checked via `Settings.canDrawOverlays(context)`.
- Settings UI provides explicit consent prompt explaining purpose before navigating user to `Settings.ACTION_MANAGE_OVERLAY_PERMISSION`.
- Instant revocation detection via `NotificationLifecycleOwner.reconcileOverlayPermission()` on application resume.

## Mandatory Pairing Behavior Invariant

Wireless ADB pairing results and codes generated by `AdbPairingService` are delivered via standard system notifications on channel `adb_pairing` (ID 1) and **never rely exclusively on overlay messages**.
